# 独立播报运行程序（v1.4.3）

生成器将自行编写的 `IndependentAnnouncer.cs` 编译结果重新命名为用户的语音包名字，用 Mono.Cecil 嵌入配置与 PCM WAV。生成的 ZIP 只有 Everest 清单、一个模块 DLL、说明和制作信息；不修改任何第三方模块，不复制任何 `.bank` 元数据。不需要模板、FMOD Studio、游戏文件或额外音频库来生成。

模块监听 Everest 的游戏 Hook，调用原方法一次，再根据游戏状态决定是否播报。没有音频的项目直接返回。每个项目有 1–5 条时独立等概率随机选择，允许重复抽中。

## 检测依据

| 事件 | 依据 |
| --- | --- |
| Demo Dash | 对齐本地 TechAnnouncer 1.0.1：仅在 `DashCoroutine` 原协程的 `MoveNext` 中，`CorrectDashPrecision` 原调用返回后仍在下蹲且校正后方向 Y≤0 时播报；不读取 `demoDashed` 标记 |
| Super | 游戏调用 `SuperJump`，跳前未下蹲 |
| Hyper | 游戏调用 `SuperJump`，跳前下蹲，且不满足 Wavedash 条件 |
| Wavedash | 下蹲 `SuperJump`，本次冲刺从空中开始、初始方向斜向下；落地压平方向时保留原始瞄准方向 |
| Wall Bounce | 游戏调用 `SuperWallJump` |
| Neutral Jump | 游戏调用 `WallJump`，调用前水平输入为零 |
| Corner Boost | 空中向面朝方向移动，抓墙跳前上方六像素没有实墙，原调用后增加了水平速度并向上跳 |
| Ultra | 对齐本地 TechAnnouncer 1.0.1：在竖直碰撞原调用中设置 `Ducking = true` 留下共享标记；普通 `Jump` 调用前，标记为真、玩家处于正常状态且合成速度平方 >57600 时播报，然后消耗标记；`SuperJump` 先清除标记，不播 Ultra |
| Fast Bubble | 原版 `BoostUpdate` 从泡泡状态返回普通冲刺或红冲刺；另可选监听 FrostHelper 的 `GenericCustomBooster.BoostUpdate`，从其动态泡泡状态手动返回普通冲刺或自定义红冲刺。每次进入最多一次，自动出口和黄泡泡超时死亡不计入 |
| 普通/带金死亡 | 原死亡调用返回尸体，且此前尚未死亡；调用前从跟随对象中检查金草莓 |
| 普通/金草莓收集 | 原调用使草莓从未收集变为已收集；同一对象不重复播报 |

检测是本项目的独立规则，不承诺与旧模板所有边界条件一致。兼容原版玩家和草莓及继承其标准行为的对象；其他模组重写动作、泡泡或收集流程时需要单独验证。特别是抓角、慢速 Ultra、变体速度、特殊地形，可能需要根据游戏内测试调整。

Ultra 不再测量 1.2 倍加速、不限制落地方向或地面／狼跳帧，也不等待跳后向上速度。普通 `Jump` 在正常状态时消耗标记，即使速度不够或该项被禁用也会消耗；其他状态的 `Jump` 保留标记。新的冲刺、离地和速度变化不会额外清除它；`SuperJump` 无条件清除后保留原有 Wave／Hyper／Super 分类。记录在模块实例内共享，与原版单模块共享标记的范围一致。

FrostHelper 兼容仅在已加载的程序集包含对应公开接口时安装，支持模块先后加载；未安装时不创建兼容监听。通过反射使用 Everest 自带的 RuntimeDetour，不增加对 FrostHelper 的硬依赖，也不打包第三方 DLL。卸载时移除事件与监听。当前接口已核对本机 FrostHelper 1.81.0；改写这些接口的其他版本需要重新核对。

Demo 的检查范围只包括原冲刺协程每次 `MoveNext` 的执行，创建、暂停、读取 `Current` 与释放时不进入这个范围。原版没有额外的去重条件，多次符合条件的方向校正调用会分别播报。方向判断使用原调用返回的校正结果，方向 Y=0 计入、Y>0 不计入；不额外限制 X。

所有 Hook 都只调用原方法一次并保留返回值，普通跳参数原样传递。冲刺协程按原顺序执行，保留每个 yield 的原始对象，并在结束或取消时释放原协程；即使原方法异常退出也会清除判定范围，检测不改变游戏物理。

## 播放与生命周期

运行时从自己的程序集读取 WAV，通过游戏已有的 FMOD Core 创建内存声音，播放到 `bus:/gameplay_sfx`。因此沿用游戏的音效音量和暂停处理，不建立另一套音频系统。首次锁定总线后刷新 Studio 命令，确保第一条声音也有可用的播放组。

语音懒加载并缓存，最多缓存所选的 65 个声音；同时播放最多八条，超过时结束最早的一条。模块总音量可设为 0–10，每项音量为 0–100，两者相乘。生成器嵌入的初始音量由设置构造函数读取，再由 Everest 恢复用户已保存的设置；不改变音频波形，避免重复生成造成音量累积。每条播放通道记录对应事件，因此调整单项音量会立即改变该项已播放的声音，静音只停止对应项目。禁用后停止全部当前语音。卸载时移除所有 Hook、停止声音、释放缓存并解锁总线。不同语音包有不同程序集身份和资源，每个包的设置、随机数及缓存独立。多个播报包同时开启会各自播报，建议只开启一个。

v1.4.2 及更早生成的语音包仍含旧检测规则。迁移时请用 v1.4.3 重新生成并替换同名 ZIP，然后重启游戏；仅更新生成器不会改变已经生成的模组。
